# v0.4.2 authenticated free-model smoke proof

## claim

On 2026-08-12, the real `survive-live` CLI completed one day with two authenticated `opencode/nemotron-3.5-lightning-free` seats when both calls used `reasoning_effort: low`. The saved result replays without another provider call.

## result

Environment: Windows, Python 3.11, OpenCode Zen chat completions, seed 17.

- Aster chose `forage`.
- Birch chose `forage`.
- 2 calls were attempted and 2 succeeded.
- the provider reported 1,258 prompt tokens, 50 completion tokens, and 0 reasoning tokens.
- both model identifiers ended in `-free`.
- the engine completed day 1 with no validation errors and no deaths.
- the result replayed identically with SHA-256 `660129c4ed0a4d67838739508ee5efddf60998a9c1422635c7d3606d30998a33`.
- a credential-shape scan found no API key in the artifact.
- 54 automated tests passed.

The local artifact is `artifacts\live-smoke-auth-nemotron-low-17.json`.

The negative control is `artifacts\live-smoke-auth-nemotron-17.json`. With provider-default reasoning, the first call exhausted all 4,096 completion tokens. The host stopped at day 0 with no successful calls and no world mutation.

## reproduce

Put a rotated OpenCode Zen key on the clipboard. Run:

```powershell
$env:PYTHONPATH = "src"
$env:OPENCODE_ZEN_API_KEY = (Get-Clipboard -Raw).Trim()
try {
  py -3.11 -m world_sim survive-live `
    --model opencode/nemotron-3.5-lightning-free `
    --model opencode/nemotron-3.5-lightning-free `
    --seed 17 --days 1 --max-calls 2 `
    --max-completion-tokens 4096 `
    --reasoning-effort low `
    --show-transcript `
    --output artifacts\live-smoke-auth-nemotron-low-17.json
} finally {
  Remove-Item Env:OPENCODE_ZEN_API_KEY -ErrorAction SilentlyContinue
}
```

Run the deterministic suite separately:

```powershell
$env:PYTHONPATH = "src"
py -3.11 -m unittest discover -s tests -v
```

## bound

This receipt proves one live, two-call integration run and offline replay. It does not prove cooperation, strategic planning, cross-model reliability, stable free-model availability, or repeatable model choices. `reasoning_effort: low` is a provider compatibility option, not a measured private-reasoning budget. The current provider reported zero reasoning tokens for these two calls.
