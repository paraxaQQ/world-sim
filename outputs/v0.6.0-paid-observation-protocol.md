# v0.6.0 paid observation protocol

## status

Frozen before provider calls, then executed once on 2026-08-13. The episode stopped at call 2 when MiniMax M3 exhausted its 1,024-token completion budget. It was not retried.

## question

When models receive the same survival rules, partial information, repeated chances to interact, and no instruction to cooperate or compete, what costly social behavior appears?

## episode

Run one exploratory episode with the calibrated `lean-camp-v1` world. The episode has one cycle and four chances. Communication is enabled as part of the base world; this is not a communication treatment and has no silent control.

Use seed `29995` and this fixed mapping:

| public name | hidden model assignment |
| --- | --- |
| Aster | `opencode-paid/deepseek-v4-flash` |
| Birch | `opencode-paid/minimax-m3` |
| Cinder | `opencode-paid/kimi-k2.6` |
| Lumen | `opencode-paid/glm-5.2` |

Freeze these inference and host settings:

| setting | value |
| --- | --- |
| cycles | `1` |
| chances per cycle | `4` |
| maximum calls | `16` |
| complete call-budget gate | required |
| maximum completion tokens | `1024` |
| configured temperature fallback | `0.2` |
| reasoning profile | `compatibility-first` |
| request timeout | `120` seconds |
| maximum authorized cost | `$0.18` |
| provider retries | `0` |
| response-repair calls | `0` |

## run

Use a fresh OpenCode Zen key. Put it in `OPENCODE_ZEN_API_KEY` only for the run. Never commit the key or place it in the command, an artifact, or `.env`.

The request controls are not uniform. DeepSeek and GLM receive thinking disabled with temperature `0.2`. Kimi receives thinking disabled and uses its provider-fixed temperature. MiniMax uses provider defaults because its current public documentation does not define an M3 thinking control.

If card-charge control matters, disable Zen auto-reload before the run. The local `$0.18` ceiling controls model-request usage, not account reloads.

```powershell
$env:PYTHONPATH = "src"
$env:OPENCODE_ZEN_API_KEY = (Get-Clipboard -Raw).Trim()
try {
  py -3.11 -m world_sim survive-live `
    --model opencode-paid/deepseek-v4-flash `
    --model opencode-paid/minimax-m3 `
    --model opencode-paid/kimi-k2.6 `
    --model opencode-paid/glm-5.2 `
    --preset lean-camp-v1 `
    --seed 29995 --cycles 1 `
    --max-calls 16 --require-complete-budget `
    --max-completion-tokens 1024 `
    --temperature 0.2 `
    --reasoning-effort compatibility-first `
    --max-paid-usd 0.18 `
    --timeout-seconds 120 `
    --show-transcript `
    --output outputs\v0.6.0-paid-observation-29995.json
  if ($LASTEXITCODE -ne 0) {
    throw "paid observation failed; preserve the artifact and do not retry"
  }
} finally {
  Remove-Item Env:OPENCODE_ZEN_API_KEY -ErrorAction SilentlyContinue
  Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
}
```

The output path must not exist before the run. The host reserves it before contacting a provider.

## cost and stopping rules

The 16-call limit covers every survivor on every chance. It does not require 16 calls because resting ends a survivor's participation for that cycle.

Before each paid request, the host prices the exact current message payload plus the full 1,024-token output allowance. It adds that bound to the greater of provider-reported or locally calculated cost from earlier successful requests. The host refuses the next request before transport if this cumulative authorization would exceed `$0.18`.

This gate assumes that the pinned Zen prices remain current, 1,024 extra input tokens cover the provider's hidden chat template, and the provider enforces the completion-token cap. A timeout can still be billed because the provider might finish after the client stops waiting. The artifact retains the authorized exposure for that failed request.

Stop after this one episode. A transport error, HTTP error, invalid provider envelope, exhausted completion budget, request cap, or cost cap ends the run. Do not retry. The strict parser does not request a repair. A malformed action or message follows the recorded world rules instead of causing a rerun.

Do not rerun because the trace is uneventful, every survivor forages, no one speaks, no transfer occurs, or one model returns malformed JSON. Those are observations from the authorized episode.

## report

Report these integrity results:

- completion or failure status
- calls attempted, succeeded, and failed for each model
- provider-resolved model IDs, token use, provider-reported cost, and conservative authorization use
- validation errors and cancelled deadline choices
- retry and repair counts, which must remain zero
- exact offline replay result and recorded source hashes

Report these world results:

- each submitted, normalized, and resolved action by public name and chance
- voluntary rest timing, forced collapses, exhaustion, deaths, and survivors
- forage, wood gathering, eating, shelter building, and final inventories and energy
- every attempted and successful `give_food` or `give_wood`, including actor, recipient, timing, energy paid, and resources transferred
- message counts and whether a message preceded a later costly transfer

`give_food` and `give_wood` are the direct costly social actions in this world. A message alone is not costly social behavior.

## claim boundary

This episode can provide one descriptive trace from seed `29995` and one fixed seat mapping. It cannot establish a model ranking, a stable model trait, a general cooperation rate, or a causal effect of communication. Model-specific or population-level claims require new seeds and name-to-seat rotations. A communication-effect claim requires a separately designed control.
