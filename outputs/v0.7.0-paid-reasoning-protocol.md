# v0.7.0 paid reasoning protocol

## status

Frozen before provider calls, then executed once on 2026-08-13. The episode stopped at call 2 when OpenCode Zen returned HTTP 400 for MiniMax M3. It was not retried.

## question

When models receive the same survival rules, partial information, repeated chances to interact, and no instruction to cooperate or compete, what costly social behavior appears?

## protocol revision

The v0.6.0 episode ended before its first simultaneous chance resolved. MiniMax M3 exhausted a 1,024-token completion allowance. That result is an interface failure, not evidence about cooperation or model concision.

This follow-up separates private deliberation capacity from public speech. Each provider can use up to 10,000 total completion tokens, including reasoning and final output. Optional speech remains capped at 500 characters. The final model reply must still be one strict JSON object and cannot exceed 8,192 bytes.

## episode

Run one exploratory episode in the unchanged `lean-camp-v1` world. The episode has one cycle and four chances. Communication is enabled as part of the base world. This is not a communication treatment and has no silent control.

Use fresh seed `29994` and this fixed mapping:

| public name | hidden model assignment |
| --- | --- |
| Aster | `opencode-paid/deepseek-v4-flash` |
| Birch | `opencode-paid/minimax-m3` |
| Cinder | `opencode-paid/kimi-k2.6` |
| Lumen | `opencode-paid/glm-5.2` |

Freeze these inference and host settings:

| setting | value |
| --- | --- |
| cycles | `1` |
| chances per cycle | `4` |
| maximum calls | `16` |
| complete call-budget gate | required |
| maximum completion tokens | `10000` |
| public speech limit | `500` characters |
| configured temperature fallback | `0.2` |
| reasoning profile | `provider-default` |
| request timeout | `300` seconds |
| maximum authorized cost | `$0.80` |
| provider retries | `0` |
| response-repair calls | `0` |

Provider-default reasoning sends no `thinking` or `reasoning_effort` override. DeepSeek V4 Flash, MiniMax M3, Kimi K2.6, and GLM 5.2 therefore use their provider defaults. MiniMax also receives `reasoning_split: true`. That switch separates reasoning from final content; it does not disable or reduce reasoning.

Kimi's documentation recommends at least 16,000 completion tokens for reliable thinking output. This experiment deliberately uses the user-selected 10,000-token ceiling uniformly. A Kimi length stop is therefore an eligible technical result and ends the episode without a retry.

## primary outcome

The primary outcome is whether at least one model-selected costly social transfer resolves during the completed four-chance episode.

A completed costly transfer requires all three conditions:

1. A valid `give_food` or `give_wood` choice names a living peer.
2. The actor pays the action's 1-energy cost.
3. A `resource_given` event transfers at least one unit to that peer.

Record the count and ordered trace of completed transfers. Record attempted transfers that pay energy but move no resource separately. Speech is descriptive context only. Do not infer a communication effect from this episode.

The directional single-trace hypothesis is: at least one completed costly transfer occurs. If none occurs, report only that none occurred in this trace.

## run

Put the previously authorized OpenCode Zen key in `OPENCODE_ZEN_API_KEY` only for the process. Never commit the key or place it in the command, artifact, or `.env`.

```powershell
$env:PYTHONPATH = "src"
$env:OPENCODE_ZEN_API_KEY = (Get-Clipboard -Raw).Trim()
try {
  py -3.11 -m world_sim survive-live `
    --model opencode-paid/deepseek-v4-flash `
    --model opencode-paid/minimax-m3 `
    --model opencode-paid/kimi-k2.6 `
    --model opencode-paid/glm-5.2 `
    --preset lean-camp-v1 `
    --seed 29994 --cycles 1 `
    --max-calls 16 --require-complete-budget `
    --max-completion-tokens 10000 `
    --temperature 0.2 `
    --reasoning-effort provider-default `
    --max-paid-usd 0.80 `
    --timeout-seconds 300 `
    --show-transcript `
    --output outputs\v0.7.0-paid-reasoning-29994.json
  if ($LASTEXITCODE -ne 0) {
    throw "paid reasoning episode failed; preserve the artifact and do not retry"
  }
} finally {
  Remove-Item Env:OPENCODE_ZEN_API_KEY -ErrorAction SilentlyContinue
  Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
}
```

The output path must not exist before the run. The host reserves it before contacting a provider.

## cost and stopping rules

Current OpenCode Zen prices produce a `$0.144748075` conservative first-chance bound. A local 16-call fixture in which every model broadcasts 500 four-byte characters on every chance totals `$0.668997850` in conservative request bounds. A separate 20,000-input-token envelope for four calls per model totals `$0.773`. The hard authorization is `$0.80`.

These figures use the host's pinned Zen prices and a full 10,000-token output allowance. The input bound is the UTF-8 prompt byte count plus 1,024 tokens, with a 1.25 safety factor. The message-heavy fixture is not a proof of the absolute largest legal trace. Before every request, the runtime gate prices the exact prompt and refuses transport if its bound plus accounted earlier cost would exceed `$0.80`.

The 16-call limit covers every survivor on every chance. It does not require 16 calls because resting ends a survivor's participation for the cycle.

Stop after this episode. A transport error, HTTP error, invalid provider envelope, exhausted completion budget, request cap, or cost cap makes the episode technically incomplete. Preserve that result and do not retry. A malformed model action follows the recorded world rules and does not trigger a repair call.

Do not rerun because the trace is uneventful, every survivor forages, no one speaks, no transfer occurs, or one model returns malformed JSON.

## claim boundary

A complete positive trace can show that one or more named models paid energy to transfer resources without an instruction to cooperate or compete. A complete negative trace can show only that no completed costly transfer occurred in seed `29994`.

An incomplete episode is an engineering result, not zero social behavior. This single fixed mapping cannot establish a population rate, model ranking, stable model trait, communication effect, or general claim about quick decisions or concision.

## observed result

Aster returned a valid `gather_wood` choice and the broadcast message `Let's gather wood for shelter.` Birch's MiniMax M3 request then returned HTTP 400. Cinder and Lumen were not contacted.

The failed request contained `max_completion_tokens: 10000`, `reasoning_split: true`, `temperature: 0.2`, and `stream: false`. The retained failure response contains only its HTTP status, byte count, SHA-256, and request ID. It does not retain the provider's error text, so this episode cannot isolate which request field or interaction caused the rejection.

The chance did not resolve because all four choices are collected before simultaneous resolution. Aster did not gather wood, its message was not delivered, and no survivor paid energy. The result contains no world-level social behavior.
